# Outputs and quality-control review

Paths below are relative to `--outdir`. They describe the publishers in [main.nf](../main.nf); files depend on selected branches, input modalities, and successful tasks. There is no FastQC or MultiQC stage in the active MRI workflows.

## Production outputs

| Path                                    | Contents and review                                                                                                                                                      |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `sub-*/ses-*/`                          | Converted BIDS NIfTI/JSON and other acquisition files, including original non-defaced anatomical images. Check naming, completeness, and metadata.                       |
| `dataset_description.json`              | Dataset metadata generated during merge; inspect the generic name and study metadata before reuse.                                                                       |
| `derivatives/dwi_ADC/`                  | ADC files separated by study-specific postprocessing.                                                                                                                    |
| `logs_dcm2bids/`                        | Conversion logs collected during merge.                                                                                                                                  |
| `modified_config.json`                  | Session-adjusted conversion config. Multiple rows share this filename; retain task-local configs for complete provenance.                                                |
| `.bidsignore`                           | Effective validator exclusions (hidden file).                                                                                                                            |
| `dataset_validation_log.txt`            | Raw verbose validator output for the merged dataset.                                                                                                                     |
| `bids_qc_summary.txt`                   | Readable gate result with errors and accepted/unaccepted warning groups.                                                                                                 |
| `derivatives/mriqc/`                    | Participant reports and IQM JSON, plus group reports/tables generated for available modalities. Group output includes copied participant results.                        |
| `derivatives/fmriprep/`                 | Participant HTML reports, anatomical/functional derivatives, confounds and other outputs generated by fMRIPrep. Exact contents depend on acquisitions and tool behavior. |
| `derivatives/defaces/sub-*/ses-*/anat/` | Anatomical outputs from the selected production defacer, including `*_defaced.nii.gz` where produced. Inspect images visually.                                           |
| `software_versions.yml`                 | Deduplicated version fragments collected by the workflow; coverage is incomplete for some modules.                                                                       |

The BIDS files are published at the output root, not in a `bids_dataset/` subdirectory. Inspect actual outputs rather than expecting every directory for every run. The derivative files are not replacements for the original anatomical data.

### Example converted dataset

Illustrative files after conversion; exact entities and modalities depend on the acquisition and dcm2bids mapping:

```text
results/
├── dataset_description.json
├── .bidsignore
├── sub-001/
│   └── ses-01/
│       ├── anat/
│       │   ├── sub-001_ses-01_T1w.nii.gz
│       │   └── sub-001_ses-01_T1w.json
│       ├── func/
│       │   ├── sub-001_ses-01_task-rest_bold.nii.gz
│       │   └── sub-001_ses-01_task-rest_bold.json
│       ├── fmap/
│       │   ├── sub-001_ses-01_phasediff.nii.gz
│       │   └── sub-001_ses-01_phasediff.json
│       └── dwi/
│           ├── sub-001_ses-01_dwi.nii.gz
│           ├── sub-001_ses-01_dwi.json
│           ├── sub-001_ses-01_dwi.bval
│           └── sub-001_ses-01_dwi.bvec
├── logs_dcm2bids/
└── derivatives/
```

`anat` contains structural images; `func` contains BOLD time series and any single-band references; `fmap` contains distortion-correction acquisitions; `dwi` contains diffusion images and gradient files. This abbreviated tree is not a complete BIDS test dataset (for example, the field-map acquisition may need additional files). Conversion of DWI does not imply diffusion preprocessing: no dedicated diffusion-analysis branch is wired into this workflow.

Unlike the prototype’s illustrative tree, the current merge does not create `participants.tsv`, a dataset README, or a `sourcedata/` copy of the DICOM inputs. Retain source data and curate study-level metadata separately.

## Diagnostics that remain in the work directory

Several module outputs are not connected to top-level publishers:

- `BIDS_QC_GATE`: `bids_qc_report.json` and `check_passed.txt`.
- `BIDS_VALIDATOR`: `dataset_validation_summary.txt` with captured exit status.
- MRIQC and fMRIPrep wrapper logs.
- Benchmark per-image metric TSV/JSON files and renderer JSON metadata.

Locate a task from its work hash in `.nextflow.log` or an enabled trace, then inspect `.command.sh`, `.command.out`, `.command.err`, `.exitcode`, and the module outputs. Do not remove work files before resolving QC and collecting the provenance you need. Gate filtering can leave a successful workflow with no downstream outputs; inspect both the summary and raw validator log.

## Enable execution reports

Timeline, report, trace and DAG are disabled in `nextflow.config`. To collect them, append these options to a run command using an existing report directory:

```bash
mkdir -p run-reports
# Append to the nextflow run command:
# -with-report run-reports/execution_report.html
# -with-timeline run-reports/execution_timeline.html
# -with-trace run-reports/execution_trace.txt
# -with-dag run-reports/pipeline_dag.html
```

Use separate filenames/directories for each invocation to retain staged-run history. The template's automated completion reports and validated samplesheet publication are not active, so do not expect `params.json`, `samplesheet.valid.csv`, or a MultiQC report to appear automatically. Preserve your submitted parameter file yourself.

## Benchmark outputs

| Path                                                          | Contents                                                     |
| ------------------------------------------------------------- | ------------------------------------------------------------ |
| `benchmark_defacing/qc/*.png`                                 | Original/defaced image comparisons for visual assessment.    |
| `benchmark_defacing/metrics/benchmark_per_subject_method.csv` | Merged per-image/method metrics and detector information.    |
| `benchmark_defacing/summary/benchmark_summary_by_method.csv`  | Aggregated method-level results.                             |
| `benchmark_defacedet/defacedet/<method>/*.deface_qc.json`     | Detector scores and classifications.                         |
| `benchmark_defacedet/defacedet/<method>/*.deface_qc_pass.txt` | Detector pass/fail flags at the wrapper's threshold of 0.5.  |
| `benchmark_defacing/defaced/`                                 | Declared defaced-image publication target; see caveat below. |

The benchmark workflow constructs `[file, rel]` maps for method-specific paths, but the top-level defaced publisher uses a static path and does not explicitly map those fields as production does. Verify publication behavior before relying on a method-specific layout; individual defacer task directories retain the generated files. The benchmark only wires dcm2bids version records into `software_versions.yml`, and its validation outputs are task-local.

See the [benchmark guide](benchmark.md) for interpretation. Detector pass/fail and intensity-change metrics are not proof that an image is safe to share.
